# 在 VS Code 中一键仿真 VHDL

安装方法见仓库 README。安装 NVC、`NVC Runner · VHDL 仿真` 和官方 `Surfer` 扩展后，打开示例文件夹 `examples/counter`。

0.2.2 起，仿真成功后默认在独立的 VS Code 窗口显示 Surfer 波形。需要并排显示时，在 VS Code 设置中搜索 `nvcRunner.waveformWindow` 并选择 `beside`。

## 自动生成测试平台（0.2.0）

打开被测设计文件（示例是 `counter.vhd`），按 `⌘⇧P` 执行 **NVC: 生成 Testbench**。向导会让你逐个设置输入端口：固定值、定时变化或周期时钟。定时变化示例 `0ns=0;20ns=1;100ns=0`；向量值示例 `x"A5"`；时钟可设置初值、开始时间和完整周期。

预览后给新测试文件起名，已有文件不会覆盖。选择 **设为仿真顶层**，确认编译顺序和时限，然后点击 ▶。生成器负责输入激励，功能检查仍需加入 `assert`；没有检查时只提示 `STIMULUS_DONE`。

计数器可以使用：结束 300ns；clk 初值 0、开始 0ns、周期 10ns；rst 为 `0ns=1;20ns=0`；en 为 `0ns=0;20ns=1;100ns=0;130ns=1`；新文件名 `tb_counter_inputs`。

## 第一次打开自己的项目

1. 用 VS Code 的“文件 → 打开文件夹”打开存放 VHDL 文件的项目文件夹，并信任这个本地项目。
2. 写设计文件（如 `counter.vhd`）和测试平台文件（如 `tb_counter.vhd`）。时钟、复位、输入变化和检查条件写在 testbench 中；NVC/Surfer 不提供 ModelSim 那样直接绘制输入激励的窗口。
3. 打开命令面板（`⌘⇧P`），运行 **NVC: 配置 VHDL 仿真**。选择源文件、按依赖关系排好编译顺序，再填测试平台的顶层实体名和 VHDL 标准，选择“运行到结束”或“运行到指定时间”。新配置默认运行到结束；已有配置优先保留当前模式，数字模式保留原时间作为输入默认值。扩展会保存 `vhdl.sim.json`。也可以直接编辑这个 JSON。

## 以后每次运行

打开任一 `.vhd` 或 `.vhdl`，点击编辑器右上角的 **▶ NVC: 运行 VHDL 仿真**，或者点击底部状态栏的 **NVC 仿真**。扩展会保存本项目未保存的文件，然后依次分析、展开、运行 testbench，生成新的 FST，成功后在独立的 VS Code 波形窗口打开 Surfer。

在 Surfer 左侧展开 `tb_counter` 等层级，点选一个实例，再单击下方 Variables 中的信号名把它加入右侧波形区；放大编辑器组可看清波形。示例里可以观察 `clk`、`rst`、`en`、`count[3:0]`。

仿真输出在 VS Code 的 **输出 → NVC 仿真**；NVC 能定位到源代码的报错会出现在 **问题** 面板。运行失败时不会更新波形；窗口中保留的是上次成功的结果。可通过运行进度通知的“取消”或命令 **NVC: 取消 VHDL 仿真** 结束运行。

`vhdl.sim.json` 中的 `sources` 顺序就是编译顺序，`top` 是 testbench 的实体名，`stopTime` 例如 `all` 或 `1us`。第三方或老师提供的预编译库若有专用目录，可填入 `libraryPaths`；扩展不会自动编译这些库。NVC 不支持的厂商专有库仍可能需要课程指定的 ModelSim/Questa 环境。

## 运行到结束（Run All，0.4.0）

`stopTime` 支持两种值：`"all"`（运行到结束）或 `"5us"` 等正整数时间上限。普通 ▶ / 状态栏按这个保存的值运行。旧项目不会自动转换；省略字段继续使用 `1us`。

如果保存的时间上限让手写 testbench 提前停止，可以按 `⌘⇧P` 执行 **NVC: 运行到结束（Run All）**，也可以在 VHDL 编辑器标题栏的“…”菜单或 VHDL 文件右键菜单中执行。此命令只为本次运行临时使用 `all`，不改写项目配置；之后的普通 ▶ 仍使用原设置。输出会明确显示“运行到结束”或本次数字上限。

运行到结束时，NVC 没有 `--stop-time` 参数，遇到 `std.env.finish`、终止性失败或没有未来事件时结束。`report` 和 `end process` 不会结束整场仿真。一直翻转的时钟会继续产生未来事件，因此有持续时钟的测试平台应在所有检查之后调用 `std.env.finish`，并使用 VHDL-2008。例如：

```vhdl
stop_simulation : process
begin
  wait for 10 us;
  report "TEST_DONE";
  std.env.finish;
  wait;
end process;
```

没有结束条件时，可通过进度通知的“取消”或 **NVC: 取消 VHDL 仿真** 中止；取消和错误不会替换上次成功波形。NVC 退出码 0 不代表已经执行了所有预期检查；请检查最终输出并按功能要求编写断言。

自动生成测试平台的“测试结束时间”仍是数字时长，用于限制激励变化，并在 TB 内生成 `finish`。它与项目运行模式分开：创建新配置使用 `all`，更新已有 `all` 时保持不变；已有数字上限过短时提高到生成 TB 的结束时间。

## 分段运行与临时修改输入（0.3.0）

按 `⌘⇧P` 运行 **NVC: 启动交互仿真**，编译现有配置并运行初始 100ns 后，波形窗口上方出现控制按钮。点 **运行一段**，输入 `100ns`；可多次推进，电路内部状态会保留。点 **继续** 以同样的分段时长持续运行，点 **暂停** 在当前段结束后暂停。

暂停后点 **强制输入**，从列表选择 `/tb_a` 等信号，输入 `'0'`、`'1'` 或匹配位宽的 `"0101"`；再运行一段观察电路响应。点 **解除强制** 后再运行，恢复原驱动。点 **读信号** 可查看此时的值。

修改代码后，先点 **结束会话**，再启动新会话或普通 ▶。testbench 的 `finish` / `stop` 已生效时也要重启，继续按钮不会越过它。暂停以段为单位，段越长，暂停等待可能越长。真实时间没有推进时仍可强制组合电路的输入。

普通仿真、交互仿真共享同一项目波形窗口，重新运行会保留信号选择与布局，关闭再打开也会恢复。想重新选择时可关闭设置 `nvcRunner.preserveWaveformLayout`。

新 Mac 首次使用交互模式，先按 README 执行 `bash tools/build-nvc-interactive.sh --install-deps`。普通 Homebrew NVC 不带此实验快照补丁。当前交互控制适合学习与基础功能仿真，不含 ModelSim 的源代码断点、单步调试和厂商库集成。
