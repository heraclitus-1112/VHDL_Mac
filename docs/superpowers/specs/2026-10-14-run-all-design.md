# NVC Runner：运行到结束（Run All）已批准设计

## 目的
避免手写 testbench 因固定 stopTime 提前停止，未执行完测试与最终 report。Exo4 当前 5us 上限截断 5.12us 的测试；本次实测移除 --stop-time 后，原 TB 在 5120ns 输出结束消息并自然退出。

## 方案比较
1. 推荐：保存运行模式，并提供单独的 Run All 命令。日常运行使用项目模式，已有项目保持数字停止时间，可用 Run All 临时覆盖本次运行。
2. 仅提供一次性 Run All 命令：修改较少，但日常运行仍可能再次截断。
3. 自动推断结束时间：无法可靠覆盖等待条件、循环和无限时钟，不采用。

## 行为
- 新命令：NVC: 运行到结束（Run All）；英文版：NVC: Run All。
- 项目配置 stopTime 支持 "all" 或现有数字时间，例如 "5us"。Run All 命令仅临时覆盖，不改写配置。
- 配置向导可选“运行到结束”或“运行到指定时间”；新配置默认运行到结束，已有配置未修改前保持原值；缺省 stopTime 继续使用旧版 1us 行为以保持兼容。
- all 模式不传 --stop-time；NVC 在 finish、终止性失败或没有未来仿真事件时退出。process 的 end process 与 report 都不是结束整场仿真的指令。
- 有持续周期时钟的 TB 应使用 std.env.finish 结束；保留现有取消操作，避免无法中止的运行。
- 自动生成 TB 的 duration 继续控制激励边界和 TB 内的 finish，与运行模式分开。创建新仿真配置使用 all；更新已有配置时保留 all，数字上限低于生成 TB 时长则按现有逻辑提高。
- 运行时在输出中明确显示“运行到结束”或具体时间上限，避免把 NVC 退出码 0 自动等同于所有断言通过。错误、取消不替换上次成功波形。
- 交互仿真继续保留分段推进，不增加不可暂停的无限 Tcl run 操作。
- 中文 main 与独立英文版本同步功能；本机安装中文版。

## 改动位置
配置校验及 NVC 参数、JSON schema、配置向导、运行命令入口、TB 生成后的配置处理、中文及英文使用说明。

## 验证
- 数字时间参数保持兼容；all 不传 --stop-time；拒绝其他非法值。
- 使用 Exo4 临时副本完整运行至 5120ns，末尾 report 出现，全部 512 组检查执行。
- finish 能终止持续时钟 TB；不含 finish 的持续时钟可取消，项目运行锁释放。
- 自动生成 TB 在预定时刻 finish，切换顶层时 all 保持不变。
- VS Code 两种命令、英文版对应入口、取消及实际新波形加载；最终保留中文版安装。

## 范围
不修改用户已有 TB 或项目配置，不自动把所有旧项目改为 all，不推断业务正确性，不加入新的交互引擎。本设计已获用户批准实现并安装。
